# Gemini Rules — UnTraceMe UI Design Architecture

> **Project:** UnTraceMe (`d:\SMT\untraceme`)
> **Created:** 2026-10-13
> **Authority:** Principal Design Architect & Staff Frontend Engineer
> **Scope:** Mandatory UI/UX, styling, component, motion, and design-token rules for all code generated by Gemini.
> **Supremacy:** This file is the single source of truth for UI decisions. When any other instruction conflicts with this file on UI/design matters, this file wins — no exceptions.

---

## 0. Architect's Mandate

**You are not a code generator. You are a design architect shipping production-grade SaaS UI.**

Every pixel, every transition curve, every type ramp value, every shadow layer, and every spacing decision in this codebase must look like it was hand-crafted by a senior design team — not spat out by an AI. The bar is Linear, Vercel, Stripe, Arc, Raycast — not "another shadcn dashboard."

### 0.1 The Three Non-Negotiables `[MANDATORY]`

1. **Hugeicons** (`@hugeicons/react`) is the only allowed icon library. Zero tolerance for substitutions.
2. **shadcn/ui** is the only allowed component primitive system. Every base UI element (Button, Card, Dialog, Tooltip, Slider, Select, etc.) MUST be sourced from `components/ui/` following shadcn/ui patterns. Do not reinvent primitives.
3. **No AI-generated UI.** Generic, template-looking, "obviously AI-made" interfaces are forbidden. Every surface must pass the "would a senior designer ship this?" test (detailed in Section 13).

### 0.2 Rule Compliance Protocol

1. **Read this file end-to-end before generating ANY UI code.** Do not skim. Do not skip.
2. Every generated file MUST be verifiable against the rules below. If a rule cannot be satisfied, stop and flag it explicitly — do not silently proceed.
3. Rules marked `[MANDATORY]` are non-negotiable. Rules marked `[PREFERRED]` have documented exceptions.
4. When unsure between two approaches, choose the one that most closely matches existing patterns in `app/_components/` and `components/ui/`.
5. Never invent new design tokens, color values, radii, or spacing units outside `globals.css`. If a value is missing, extend the token system — do not hardcode.
6. **If a generated UI element would not pass review at Linear, Vercel, or Stripe — rewrite it.**

## 1. Project Identity & Tech Stack Lock-in

### 1.1 Stack `[MANDATORY]`

| Layer | Technology | Lock Status |
|---|---|---|
| Framework | Next.js 16 App Router (root `app/`, no `src/`) | 🔒 Locked |
| Language | TypeScript (strict mode) | 🔒 Locked |
| Styling | Tailwind CSS v4 (CSS-variable-first) | 🔒 Locked |
| Icons | `@hugeicons/react` — **only** | 🔒 Locked |
| Component Primitives | **shadcn/ui** (Radix-based) — **only** | 🔒 Locked |
| Fonts | Inter (primary) / Geist Sans (alt) via `next/font` | 🔒 Locked |
| Animations | Framer Motion (for orchestrated motion) + Tailwind transitions | 🔒 Locked |
| Theme Engine | `next-themes` for dark/light switching | 🔒 Locked |

> **Directory convention:** Project uses **no `src/` directory**. App Router lives at root `app/`, shared components at root `components/`, library code at root `lib/`, config at root `config/`. Never create a `src/` folder.

### 1.2 Forbidden Substitutions `[MANDATORY]`

- ❌ No `lucide-react`, `react-icons`, `@heroicons/react`, `feather-icons`, `@phosphor-icons`, or ANY other icon library. **Hugeicons only.**
- ❌ No hand-rolled Button, Dialog, Tooltip, Select, Slider, Dropdown, Tabs, Accordion, etc. **Always use shadcn/ui primitives.** If a primitive is missing from `components/ui/`, install it via the shadcn CLI (`npx shadcn@latest add <component>`) — do not write it from scratch.
- ❌ No `styled-components`, `emotion`, `CSS Modules`, or inline `style={{}}` for themeable values.
- ❌ No Material UI, Ant Design, Chakra UI, Mantine, or any other component library. **shadcn/ui only.**
- ❌ No Tailwind v3 `tailwind.config.js` color extensions — use CSS variables in `globals.css`.
- ❌ No raw hex/rgb values inside component files for theme colors.
- ❌ No `!important` overrides unless documented as an edge case.

### 1.3 shadcn/ui Customization Discipline `[MANDATORY]`

shadcn/ui is a starting point, not a finish line. Every primitive MUST be customized to match UnTraceMe's design language:

- Default shadcn styling is the **floor**, not the **ceiling**.
- Override `className` props with token-backed utilities: `bg-primary`, `text-foreground`, `rounded-radius`, `shadow-md`.
- Add micro-interactions: hover lift, focus ring glow, press scale (see Section 9).
- Never ship a default shadcn Button without adjusting radius, padding rhythm, and transition curve to match the rest of the suite.
- Variant extensions go in the primitive file itself (`components/ui/button.tsx`), not scattered across feature components.
- **shadcn config note:** Set `"components": "@/components/ui"` and `"aliases.utils": "@/lib/utils"` in `components.json` — no `src/` path segments anywhere.

## 2. Design Token System

### 2.1 Token Source of Truth `[MANDATORY]`

All theme tokens MUST be defined as CSS custom properties in `app/globals.css` under `:root` (light) and `.dark` (dark theme). Tailwind v4 references these tokens via `@theme inline`.

**Required token categories:**

```css
:root {
  /* Surfaces */
  --background;
  --foreground;
  --card;
  --card-foreground;
  --muted;
  --muted-foreground;
  --popover;
  --popover-foreground;

  /* Brand / Accents */
  --primary;
  --primary-foreground;
  --accent;
  --accent-foreground;
  --secondary;
  --secondary-foreground;
  --destructive;
  --destructive-foreground;
  --success;
  --warning;
  --info;

  /* Hairlines & Borders */
  --border;
  --input;
  --ring;

  /* Geometry */
  --radius;              /* base radius; derived: --radius-sm/md/lg/xl/full */
  --radius-sm;
  --radius-md;
  --radius-lg;
  --radius-xl;
  --spacing-unit;        /* base 4px scale */

  /* Elevation */
  --shadow-xs;
  --shadow-sm;
  --shadow-md;
  --shadow-lg;
  --shadow-xl;
  --shadow-2xl;
  --shadow-glow;         /* electric accent glow */
  --shadow-inner;

  /* Typography */
  --font-sans;
  --font-mono;
  --font-display;        /* optional: for hero / display copy */

  /* Transitions */
  --transition-fast;     /* 120ms ease-out */
  --transition-base;     /* 200ms cubic-bezier(0.4, 0, 0.2, 1) */
  --transition-slow;     /* 320ms cubic-bezier(0.16, 1, 0.3, 1) */
  --ease-spring;         /* cubic-bezier(0.16, 1, 0.3, 1) — for delightful motion */
  --ease-emphasized;     /* cubic-bezier(0.2, 0, 0, 1) — for state transitions */
}
```

### 2.2 Color Palette Direction `[MANDATORY]`

- **Neutrals:** Deep slate / zinc family — `#0a0a0c` → `#fafafa` range. NEVER pure `#000` or pure `#fff`.
- **Accent:** Subtle electric — pick ONE primary accent (indigo `#6366f1`, violet `#7c3aed`, or cyan `#06b6d4`) and use it consistently across the entire suite. No rainbow palettes.
- **Surface depth:** Background `#fafafa` (light) / `#0a0a0c` (dark). Card surface `#ffffff` / `#121214`. Hairline borders `rgba(0,0,0,0.08)` / `rgba(255,255,255,0.08)`.
- **Gradients:** Use sparingly. When used, gradient must be subtle (max 15% lightness shift) and use the same hue family — never clash hues.
- **Dark mode:** Must be a true dark, not "inverted light". Use slate/zinc with intentional contrast ratios — every text token must hit WCAG AA on the chosen surface.

### 2.3 Token Usage in Components `[MANDATORY]`

- Consume tokens via Tailwind v4 utility classes: `bg-background`, `text-foreground`, `border-border`, `rounded-radius`, `shadow-md`.
- For one-off values not yet tokenized, use Tailwind arbitrary values like `h-[calc(100vh-4rem)]` — never inline `style={{}}` for themeable values.
- NEVER hardcode `text-[#6366f1]` or `bg-[#0a0a0c]` — always route through the token.

## 3. Iconography Rules (Hugeicons) `[MANDATORY]`

### 3.1 Library Lock

- Import from `@hugeicons/react` only.
- This is the **only** permitted icon library. No exceptions, no "just this once", no fallbacks.

### 3.2 Variant Discipline

- **Duotone** variant: primary UI affordances, hero feature highlights, dashboard tool cards.
- **Solid** variant: status indicators, badges, dense UI (toolbar clusters).
- **Stroke** variant: secondary / utility actions, form adornments, navigation items.
- Pick ONE variant family per visual context and stay consistent within that surface. Do not mix variants within the same toolbar, card, or list.

### 3.3 Usage Pattern `[MANDATORY]`

```tsx
// ✅ Correct — Hugeicons only
import { HomeIcon, Copy01Icon, Download04Icon } from "@hugeicons/react";

<HomeIcon className="size-5 text-foreground" />

// ❌ Forbidden — wrong library
import { Home } from "lucide-react";
<Home className="w-5 h-5" />

// ❌ Forbidden — emoji as functional icon
<button>🏠 Home</button>
```

### 3.4 Sizing & Color `[MANDATORY]`

- Size via `size-4`, `size-5`, `size-6` Tailwind utilities — NEVER inline `width`/`height` props.
- Color via `text-*` token utilities — NEVER `fill-*`, `stroke-*`, or `color` prop.
- Icon + label pairs: icon `size-4` with `text-sm` label, `gap-2` spacing.
- Icon-only buttons: minimum touch target `size-9` (`min-h-9 min-w-9`) on mobile.

### 3.5 Icon Selection Craft `[MANDATORY]`

- Do NOT pick the first matching icon. Browse the Hugeicons catalog and select the variant that best matches the semantic meaning.
- A "download" action should use `Download04Icon` or `Download07Icon` (the more refined variants), not the generic `Download01Icon`.
- Match icon weight to context: heavy UI → solid/duotone; airy UI → stroke.
- Maintain an icon vocabulary doc at `docs/icon-vocabulary.md` listing every icon used and its semantic meaning — to prevent drift.

### 3.6 Forbidden Patterns

- ❌ Mixing icon libraries in the same file or surface.
- ❌ Using emoji as functional icons (only allowed in marketing copy).
- ❌ Re-coloring icons with non-token colors.
- ❌ Scaling icons beyond `size-8` for inline UI (use illustration instead).
- ❌ Reusing the same icon for different semantic actions.

## 4. Component Architecture

### 4.1 Modular Route Structure `[MANDATORY]`

Every tool lives in its own route with a private `_components` directory:

```
app/<tool-slug>/
├── page.tsx                  # Tool entry — composition only, no business logic
└── _components/
    ├── <feature>-pane.tsx    # Dedicated sub-UI blocks
    ├── <feature>-controls.tsx
    └── <feature>-<role>.tsx
```

- `_components` is **private** (Next.js `_` prefix) — not addressable as a route.
- Tool-specific components NEVER live in `components/` — they live inside the tool's `app/<tool-slug>/_components/`.
- A tool's `_components/` MUST NEVER be imported from outside that tool.

### 4.2 Shared vs Private Components

| Location | Purpose |
|---|---|
| `app/_components/` | Suite-wide shared: navbar, footer, ad slots, tool card |
| `components/ui/` | **shadcn/ui base primitives** — Button, Card, Badge, Slider, Dialog, Tooltip, Select, etc. |
| `components/` | Other reusable shared components (non-primitive, non-tool-specific) |
| `app/<tool>/_components/` | Tool-private components (never imported outside the tool) |
| `lib/` | Business logic engines, utils, integrations (no JSX) |
| `config/` | Site config, tools registry, SEO metadata |
| `hooks/` | Shared React hooks (optional, can also live in `lib/hooks/`) |

### 4.3 Component Composition Rules `[MANDATORY]`

- `page.tsx` files are **composition-only** — they assemble components, never contain business logic or inline styles.
- Max component file length: **250 lines**. Split if exceeded — no exceptions.
- Each component must accept `className` as a prop and merge it with `cn()` from `lib/utils.ts`.
- Default exports only for `page.tsx`. Named exports for all other components.
- **Every component must be a client component ONLY if it uses hooks/interactivity** — otherwise it stays a server component. Mark `"use client"` deliberately, not by default.

### 4.4 Component Naming Convention `[MANDATORY]`

- **PascalCase** for component exports: `text-editor-pane.tsx` exports `TextEditorPane`.
- **kebab-case** for filenames (Next.js convention).
- Suffix convention:
  - `*-pane.tsx` — primary content surface
  - `*-controls.tsx` — user input controls
  - `*-meter.tsx` — visualization / gauge
  - `*-toolbar.tsx` — action bar
  - `*-badge-list.tsx` — enumeration displays
  - `*-actions.tsx` — action button group
  - `*-dialog.tsx` — modal surfaces
  - `*-empty-state.tsx` — zero-data states

### 4.5 shadcn/ui Primitive Discipline `[MANDATORY]`

- Every primitive in `components/ui/` follows the shadcn/ui pattern: Radix primitive + Tailwind styling + `cn()` merge + forwardRef.
- Extend variants via `cva` (class-variance-authority) — never via conditional `if/else` className strings.
- Never override shadcn primitive internals from feature components — extend via `className` prop only.
- If a feature needs a primitive shadcn doesn't ship (rare), build it as a Radix-based component following the same pattern and document it in `docs/custom-primitives.md`.
- shadcn `components.json` MUST be configured with these aliases (no `src/` segments):
  ```json
  {
    "aliases": {
      "components": "@/components",
      "ui": "@/components/ui",
      "utils": "@/lib/utils",
      "lib": "@/lib",
      "hooks": "@/hooks"
    }
  }
  ```

## 5. Styling Discipline

### 5.1 Tailwind v4 + CSS Variable Integration `[MANDATORY]`

- Tailwind utility classes are the primary styling mechanism.
- For theme-aware colors, ALWAYS use the Tailwind alias backed by a CSS variable (e.g. `bg-primary`, not `bg-[var(--primary)]`).
- `cn()` helper from `lib/utils.ts` is the only way to merge class lists. Never use template literal concatenation.

```tsx
// ✅ Correct
import { cn } from "@/lib/utils";
import { Button } from "@/components/ui/button";

<Button className={cn("bg-primary text-primary-foreground", className)} />

// ❌ Forbidden — inline style for theme value
<button style={{ background: "var(--primary)" }} />

// ❌ Forbidden — template literal class merge
<button className={`bg-primary ${isActive ? "bg-accent" : ""}`} />
```

### 5.2 Spacing & Layout `[MANDATORY]`

- Use Tailwind spacing scale (`gap-2`, `p-4`, `mt-6`) — do not invent arbitrary pixel values.
- Page max-width: `max-w-7xl` for suite dashboard, `max-w-6xl` for tool workspaces, `max-w-3xl` for article / doc content.
- Vertical rhythm: section spacing `py-12 md:py-16 lg:py-20`, element spacing `gap-4` or `gap-6`.
- Card padding: `p-4 md:p-6`. Dense data tables: `p-3 md:p-4`.
- **Optical alignment over mathematical alignment.** When icons sit next to text, nudge icons by 1px (e.g. `-mt-px`) to optically center — never trust pure math.

### 5.3 Border Radius `[MANDATORY]`

- Base token: `--radius` (recommend `0.625rem`).
- Derived scale: `rounded-sm` (4px), `rounded-md` (8px), `rounded-lg` (12px), `rounded-xl` (16px), `rounded-full`.
- Cards: `rounded-lg`. Buttons: `rounded-md`. Pills/badges: `rounded-full`. Inputs: `rounded-md`.
- Stay consistent — do not mix `rounded-md` and `rounded-lg` within the same surface without intent.

### 5.4 Shadows `[MANDATORY]`

- Default surfaces: `shadow-sm`.
- Elevated cards / popovers: `shadow-md`.
- Modals / dialogs: `shadow-lg`.
- Accent glow (rare, hero CTAs only): `shadow-glow`.
- NEVER use raw `box-shadow` in component files.
- Layer shadows for depth — never single-layer harsh shadows.

### 5.5 Typography `[MANDATORY]`

- Font: `Inter` via `next/font/google`, set as `--font-sans`.
- Headings: `font-semibold tracking-tight` (NEVER `font-bold` for headings — too heavy for modern SaaS).
- Body: `text-sm md:text-base leading-relaxed` (`leading-7` for long-form).
- Display hero text: `text-4xl md:text-5xl lg:text-6xl font-semibold tracking-tight`.
- Numeric / stat displays: `tabular-nums font-mono` — NEVER `font-mono` for body UI text.
- Letter-spacing: `tracking-tight` for headings, `tracking-normal` for body, `tracking-wide uppercase text-xs` for labels/eyebrows.
- Line-height rhythm: 1.2 for headings, 1.5–1.6 for body.
- **NEVER use `font-bold` as a default.** Reserve it for emphasis only.

### 5.6 Borders & Hairlines `[MANDATORY]`

- Borders must be 1px hairlines — `border` utility, never `border-2` unless intentional emphasis.
- Border color: always `border-border` token, never raw `border-gray-200`.
- Subtle separation: prefer `divide-y divide-border` over individual `border-b` on each child.

### 5.7 Animations & Motion `[MANDATORY]`

- Default transition: `transition-base` (200ms `cubic-bezier(0.4, 0, 0.2, 1)`) applied via `transition-colors`, `transition-all`, etc.
- Hover lifts: `hover:-translate-y-0.5 transition-transform duration-200`.
- Press feedback: `active:scale-[0.98] transition-transform`.
- Focus ring: `focus-visible:ring-2 focus-visible:ring-ring focus-visible:ring-offset-2 focus-visible:ring-offset-background`.
- Spring motion (orchestrated): use Framer Motion with `ease: [0.16, 1, 0.3, 1]` for delightful entrances.
- Custom keyframes MUST be defined in `globals.css` and referenced via Tailwind `animate-*` utilities.
- **Motion is communication, not decoration.** Every animation must signal a state change. No idle pulsing, no decorative motion.

## 6. Responsive Design Rules

### 6.1 Breakpoints `[MANDATORY]`

Tailwind defaults: `sm` (640px), `md` (768px), `lg` (1024px), `xl` (1280px), `2xl` (1536px).
- Design mobile-first, layer on `md:` and `lg:` adjustments.
- Ultra-wide (`2xl`+): cap content width — do not stretch beyond `max-w-7xl` / `max-w-screen-2xl`.

### 6.2 Mandatory Responsive Behaviors `[MANDATORY]`

- Navigation: collapse to hamburger / sheet drawer below `md`.
- Tool grids: `grid-cols-1` mobile → `grid-cols-2` sm → `grid-cols-3` lg → `grid-cols-4` xl.
- Text scaling: hero `text-3xl` mobile → `text-5xl` xl.
- Touch targets: minimum `44×44px` (`min-h-11 min-w-11`) for interactive elements on mobile.
- Forms: full-width inputs on mobile, constrained widths (`max-w-md`) on desktop.
- Sidebars: collapse below content on mobile, fixed sidebar on `lg+`.

### 6.3 No Horizontal Scroll `[MANDATORY]`

- Test all layouts at 320px viewport width.
- Use `overflow-x-auto` for tables and horizontal carousels — never break page width.
- Long URLs / strings: `break-words` or `truncate` with `title` attribute.

## 7. Accessibility Standards `[MANDATORY]`

### 7.1 Semantic HTML

- Use semantic elements: `<nav>`, `<main>`, `<section>`, `<article>`, `<aside>`, `<header>`, `<footer>`.
- Buttons are `<button>`, links are `<a>`. NEVER use `<div onClick>` for interactive elements.

### 7.2 Keyboard Navigation

- All interactive elements must be focusable via Tab.
- Focus ring: `focus-visible:ring-2 focus-visible:ring-ring focus-visible:ring-offset-2 focus-visible:ring-offset-background`.
- Modal dialogs: trap focus, restore on close (Radix handles this — use shadcn Dialog).
- Skip-to-content link on every page.

### 7.3 ARIA & Labels

- Every icon-only button MUST have `aria-label`.
- Form inputs MUST have associated `<label>` or `aria-labelledby`.
- Status indicators use `role="status"` or `role="alert"`.
- Decorative icons: `aria-hidden="true"`.
- Loading states: `aria-busy="true"` on the container.

### 7.4 Color Contrast

- WCAG AA minimum: 4.5:1 for body text, 3:1 for large text and UI components.
- NEVER rely on color alone to convey state — pair with icon, label, or shape.
- Test dark mode contrast independently — light-mode AA does not imply dark-mode AA.

### 7.5 Motion Sensitivity

- Respect `prefers-reduced-motion: reduce` — disable non-essential animations.
- Wrap Framer Motion orchestrations in `useReducedMotion()` checks.

## 8. AdSense Integration Rules `[MANDATORY]`

### 8.1 Placement Principles

- Ads must NEVER cover or push critical UI elements.
- High-viewability slots: above-the-fold leaderboard (`728×90`), in-content rectangle (`336×280`), sidebar skyscraper (`160×600`).
- Minimum 1 ad slot per tool page, max 3 per page (AdSense policy compliance).

### 8.2 Ad Container Component

- All ads rendered via `<AdContainer slot="..." />` from `app/_components/ad-container.tsx`.
- Ad slots must be visually distinct from content (subtle border or muted background) — NOT disguised.
- Responsive ad units: `data-ad-format="auto"` with `data-full-width-responsive="true"`.

### 8.3 Compliance

- Every page must have accessible Privacy Policy, Terms of Service, and Contact links in the footer.
- Ads loaded via the official AdSense script in `layout.tsx` — defer until after first paint.

## 9. Micro-Interaction Craft `[MANDATORY]`

This is what separates AI-generated UI from principal-crafted UI. Every interactive element MUST have deliberate micro-feedback:

### 9.1 Button States
- **Default:** token-defined background.
- **Hover:** `hover:brightness-110` or subtle `bg-primary/90` shift + `-translate-y-0.5`.
- **Active/Press:** `active:scale-[0.98]` + brightness shift down.
- **Focus-visible:** ring-2 with offset.
- **Disabled:** `disabled:opacity-50 disabled:pointer-events-none`.
- **Loading:** swap label with spinner (Hugeicons `Loading03Icon` with `animate-spin`).

### 9.2 Card Hover
- `hover:shadow-md hover:-translate-y-0.5 transition-all duration-200 ease-[cubic-bezier(0.16,1,0.3,1)]`.
- Cursor: `cursor-pointer` only if clickable.

### 9.3 Form Inputs
- Focus: `focus-visible:ring-2 focus-visible:ring-ring` + subtle border brightening.
- Validation error: border shifts to `destructive`, helper text appears with `animate-in fade-in slide-in-from-top-1`.
- Success: border shifts to `success` token, checkmark icon (`Tick01Icon` or `Tick02Icon`) appears.

### 9.4 Toast Notifications
- Use shadcn `sonner` — NEVER a custom toast implementation.
- Position: bottom-right on desktop, top-center on mobile.
- Duration: 4s default, 6s for errors, 8s for warnings.

### 9.5 Empty States
- NEVER ship a bare "No data" text. Every empty state has: illustration (Hugeicons duotone at `size-16`), headline, supporting copy, and a primary CTA.
- Use `EmptyState` shared component from `app/_components/empty-state.tsx`.

### 9.6 Loading States
- Initial page load: skeleton screens (shadcn `Skeleton`), NEVER spinners.
- Action feedback (button click): inline spinner inside the button.
- Long async (image sanitize): progress bar with percentage + animated Hugeicons.

## 10. File Naming & Export Conventions `[MANDATORY]`

### 10.1 Naming

- Directories & files: `kebab-case` (e.g. `text-editor-pane.tsx`).
- Components: `PascalCase` exports.
- Hooks: `use-<verb>-<noun>.ts` (e.g. `use-image-sanitize.ts`).
- Utils: `<domain>.ts` (e.g. `metadata-scanner.ts`).
- API routes: `route.ts` inside `app/api/<resource>/`.
- Types: `<domain>-types.ts` or co-located in component file if local-only.
- Config files: `config/<domain>.ts` (e.g. `config/tools-registry.ts`).
- Hooks: `hooks/use-<verb>-<noun>.ts` or `lib/hooks/use-<verb>-<noun>.ts`.

### 10.2 Exports

- `page.tsx`: `export default function PageName()`.
- All other components: named exports (`export function ComponentName()`).
- Utilities: named exports only.
- Avoid `export default` for non-page modules (improves refactor-ability).

### 10.3 Import Order `[MANDATORY]`

```tsx
// 1. React / Next.js
import { useState } from "react";
import Link from "next/link";

// 2. Third-party libraries (Hugeicons, Framer Motion, etc.)
import { HomeIcon } from "@hugeicons/react";
import { motion } from "framer-motion";

// 3. shadcn/ui primitives
import { Button } from "@/components/ui/button";
import { Card } from "@/components/ui/card";
import { Dialog } from "@/components/ui/dialog";

// 4. Shared suite components
import { SiteNavbar } from "@/app/_components/site-navbar";

// 5. Tool-private components
import { TextEditorPane } from "./_components/text-editor-pane";

// 6. Lib utilities
import { cn } from "@/lib/utils";

// 7. Types & config
import type { ToolConfig } from "@/config/tools-registry";
```

## 11. Tool Registry Pattern `[MANDATORY]`

Every tool must be registered in `config/tools-registry.ts` with this schema:

```ts
export interface ToolConfig {
  slug: string;              // URL segment, e.g. "text-humanizer"
  title: string;             // Display title
  description: string;       // 1-line value prop
  icon: HugeiconsIconName;   // Hugeicons identifier
  category: "text" | "image" | "audio" | "video" | "utility";
  status: "live" | "beta" | "coming-soon";
  href: string;              // /<slug>
  accentColor?: string;      // CSS variable name for tool-specific accent
}
```

- The dashboard (`app/page.tsx`) renders the grid from `tools-registry` — NEVER hardcode tool cards.
- New tools are added by appending to the registry array, not by editing the dashboard.

| First Contentful Paint | < 1.5s |
| Largest Contentful Paint | < 2.5s |
| Cumulative Layout Shift | < 0.05 |
| Total JS shipped (per route) | < 150KB gzipped |
| Image Sanitizer client bundle | < 80KB (excluding React) |

- Lazy-load below-the-fold components with `next/dynamic`.
- Use `next/image` for all raster images. SVG icons (Hugeicons) load as React components.
- Preload critical fonts via `next/font`.

## 13. Anti AI-Generated UI Manifesto `[MANDATORY]`

**This is the most important section.** AI-generated UI has telltale signs — generic templates, lazy spacing, default shadcn look without customization, copy-paste Tailwind class dumps, no micro-interactions, inconsistent rhythm. All of these are forbidden.

### 13.1 The "Would a Senior Designer Ship This?" Test

Before finalizing ANY UI element, ask:

1. Would this pass review at Linear, Vercel, Stripe, Arc, Raycast, or Resend?
2. Is every spacing value intentional, or did I just use `p-4` because it's the default?
3. Does this surface have at least one moment of delight (motion, detail, craft)?
4. Is the typography hierarchy clear at a 3-second glance?
5. Could a designer reverse-engineer the spacing system from this output?
6. Did I customize the shadcn primitive, or am I shipping the default?
7. Is there a Hugeicons icon where a generic emoji or stock SVG would have been?
8. Does the dark mode look intentional, or just an inverted light mode?

If ANY answer is "no" or "not sure" — rewrite the element.

### 13.2 Forbidden AI-Generated UI Telltale Signs `[MANDATORY]`

- ❌ **Lazy centered everything.** Centered hero + centered cards + centered CTA = obvious AI. Use intentional asymmetric layouts, optical alignment, grid rhythm.
- ❌ **Default shadcn styling untouched.** shadcn out of the box looks generic. Every primitive MUST be customized: radius, padding, transitions, hover states.
- ❌ **Copy-paste Tailwind class dumps.** 30-character className strings with no rhythm = AI laziness. Extract repeated patterns to shared components or `cva` variants.
- ❌ **No micro-interactions.** A button without hover/active/focus states is AI-generated by default.
- ❌ **`p-4 gap-4` everywhere.** Vary spacing intentionally — `p-6` for cards, `p-4` for controls, `gap-2` for tight clusters, `gap-8` for section breaks.
- ❌ **`text-gray-500` / `bg-gray-100`** — never use Tailwind's default gray scale. Always `text-muted-foreground` / `bg-muted` tokens.
- ❌ **`font-bold` headings.** Modern SaaS uses `font-semibold tracking-tight`. `font-bold` looks dated.
- ❌ **Emoji as icons.** Functional icons must be Hugeicons. Emoji only in marketing copy.
- ❌ **Default focus rings (`focus:ring-2 focus:ring-blue-500`)** — use `focus-visible:ring-ring` token.
- ❌ **Generic "Lorem ipsum" copy.** Every string in the UI must be intentional, branded, and copywritten — see Section 14.
- ❌ **Same border radius on everything.** Cards `rounded-lg`, buttons `rounded-md`, badges `rounded-full` — vary intentionally.
- ❌ **`shadow-2xl` everywhere for "depth".** Use layered subtle shadows, not nuclear glow.
- ❌ **Loading spinners instead of skeletons.** Skeletons signal care; spinners signal "I gave up".
- ❌ **Empty states that just say "No data".** See Section 9.5.
- ❌ **`overflow-hidden` to mask layout bugs.** Fix the layout, don't hide the symptom.
- ❌ **Inconsistent icon weights.** Mixing duotone + stroke + solid within the same toolbar = AI laziness.
- ❌ **`grid-cols-3` everywhere.** Responsive grid with intentional breakpoints, not a fixed 3-column dump.

### 13.3 Required Craft Elements (Per Surface) `[MANDATORY]`

Every major surface (page, tool workspace, dashboard) MUST include at least 4 of:

1. **Intentional motion** — entrance animations, hover lifts, state transitions with proper easing.
2. **Customized shadcn primitives** — at least one primitive with extended `cva` variants beyond the default.
3. **Hugeicons duotone or solid** for primary affordances (not just stroke everywhere).
4. **Skeleton loaders** for async content (not spinners).
5. **Empty states** with illustration + copy + CTA (not "no data").
6. **Toast feedback** for user actions (sonner).
6. **Optical alignment** — icons nudged, text baselines aligned, numeric values tabular.
7. **Subtle gradient or texture** in hero / banner areas (not flat fill).
8. **Hover state on every interactive element** — never a static button.
9. **Keyboard focus rings** visible on Tab navigation.
10. **Reduced-motion fallbacks** for accessibility.

### 13.4 Visual Hierarchy Discipline `[MANDATORY]`

- ONE primary action per surface. Everything else is secondary or tertiary.
- Visual weight: `primary` > `secondary` > `ghost` > `link`. Never two primary buttons side-by-side.
- Whitespace is a design element — do not fill every pixel. Linear-grade restraint.
- Eyebrow labels (`text-xs uppercase tracking-wide text-muted-foreground`) for section context.
- Use `divide-y divide-border` for stacked lists, not individual `border-b` per item.

### 13.5 Copywriting Discipline `[MANDATORY]`

UI is 50% text. AI-generated copy is a telltale sign of AI-generated UI.

- No "Welcome to..." or "Discover..." — write like a product, not a brochure.
- Button labels: verb + noun ("Sanitize Image", not "Submit"). Max 3 words.
- Empty states: specific to context ("No images uploaded yet — drag a file to begin sanitizing").
- Tooltips: terse, helpful ("Strips EXIF, IPTC, XMP, and C2PA markers — 100% in your browser").
- Error messages: actionable ("File exceeds 10MB — try a smaller image", not "Error occurred").
- Microcopy: branded voice — confident, technical, slightly witty. Not corporate.

## 14. Anti-Patterns — Master Forbidden List `[MANDATORY]`

1. ❌ Hardcoding color hex values inside `.tsx` files.
2. ❌ Using any icon library other than `@hugeicons/react`.
3. ❌ Using any component library other than shadcn/ui.
4. ❌ Hand-rolling primitives that shadcn already ships (Button, Dialog, Tooltip, etc.).
5. ❌ Inline `style={{}}` for themeable values (only allowed for dynamic computed values like canvas positions).
6. ❌ Placing tool-private components in `components/` (root shared) — they must live in `app/<tool>/_components/`.
7. ❌ Importing from another tool's `_components/` directory.
8. ❌ Using `any` TypeScript type — use `unknown` + type narrowing or proper interfaces.
9. ❌ Client-side data fetching in tool pages without Suspense boundaries.
10. ❌ Server actions inside `_components/` (those are client components).
11. ❌ More than 250 lines in a single component file.
12. ❌ Mixing light/dark theme tokens mid-component (pick one mode, derive from `:root`).
13. ❌ Adding AdSense script tags inside individual pages (only in `layout.tsx`).
14. ❌ Skipping the audit trail file after completing a feature.
15. ❌ Default shadcn primitives shipped without customization.
16. ❌ Emoji used as functional icons.
17. ❌ Spinners where skeletons belong.
18. ❌ "No data" empty states.
19. ❌ `font-bold` as default heading weight.
20. ❌ `text-gray-*` / `bg-gray-*` raw Tailwind colors.
21. ❌ Multiple primary buttons on the same surface.
22. ❌ Generic "Lorem ipsum" or templated copy.
23. ❌ `overflow-hidden` used to mask layout bugs.
24. ❌ Inconsistent icon variant weights within the same surface.
25. ❌ Skipping micro-interactions on interactive elements.

## 15. Audit Trail Requirement `[MANDATORY]`

After completing any UI feature, milestone, or design change:

1. Create `docs/context-<feature-name>-YYYY-MM-DD.md`
2. Include:
   - Feature summary (what was built)
   - Files touched (with paths)
   - Design tokens used / introduced
   - Hugeicons icons added (with semantic meaning)
   - shadcn primitives used or extended
   - Micro-interactions implemented
   - Ad slots placed
   - Accessibility verification (manual checklist results)
   - "Senior designer review" — explicitly call out craft decisions made
   - Screenshots or Loom link (if applicable)
   - Open follow-ups / known issues
3. Append entry to `docs/CHANGELOG.md` if present.
